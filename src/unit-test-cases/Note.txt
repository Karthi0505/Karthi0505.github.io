

install these packages:

1) npm install -D jest
2) npm install -D @testing-library/react

3) npm install -D @testing-library/user-event

// User Events (click, type, select, etc.)

4) npm install -D @testing-library/jest-dom

// Jest DOM Matchers example:
/*
toBeInTheDocument()
toHaveValue()
toBeChecked()
*/

5) npm install -D babel-jest @babel/core @babel/preset-env @babel/preset-react

// Babel Support for JSX (if using Jest directly)
/*
Install this package and Create:
    ---------------
    babel.config.js
    ---------------
    module.exports = {
    presets: [
        '@babel/preset-env',
        '@babel/preset-react'
    ]
    };

*/
--------------------------

6) npm install -D ts-jest @types/jest
// Install this for TypeScript Projects
/*
Generate config:
    npx ts-jest config:init
*/
----------------------------------------------


Setup File
Create:
    src/setupTests.ts

    Typescript:
    
    import '@testing-library/jest-dom';
    ----------------------------------------


    jest.config.js
    ---------------
    module.exports = {
        testEnvironment: 'jsdom',
        setupFilesAfterEnv: [
            '<rootDir>/src/setupTests.ts'
        ]
    };
    ---------------------------------------------

Install jsdom:
    npm install -D jest-environment-jsdom
---------------------------------------------

Add Script:

    {
        "scripts": {
            "test": "jest"
        }
    }
-------------------------------------

Run:
    npm test
-------------------------------------

Recommended for Vite (Much Easier)
Most React + Vite projects nowadays use Vitest instead of Jest because it works out of the box.

npm install -D vitest jsdom
npm install -D @testing-library/react
npm install -D @testing-library/jest-dom
npm install -D @testing-library/user-event

--------------------------------------------------------------------------------------------
Uninstalling previous packages
----------------------------------------------

Keep these (used by both Jest and Vitest)
-----------------------------
@testing-library/react
@testing-library/jest-dom
@testing-library/user-event
jsdom
-----------------------------

You can uninstall these Jest-specific packages
----------------------------
npm uninstall jest
npm uninstall ts-jest
npm uninstall @types/jest
npm uninstall babel-jest
npm uninstall @babel/core
npm uninstall @babel/preset-env
npm uninstall @babel/preset-react
npm uninstall jest-environment-jsdom
--------------
Or in one command:
    npm uninstall jest ts-jest @types/jest babel-jest @babel/core @babel/preset-env @babel/preset-react jest-environment-jsdom
-------------------------------------------------------------------------------------------------
------------------------------------------------------------------------------------------------

Add to vite.config.ts:

/// <reference types="vitest" />
import { defineConfig } from 'vitest/config'

export default defineConfig({
  test: {
    globals: true,
    environment: 'jsdom',
    setupFiles: './src/setupTests.ts',
  },
});
-----------------------

Create src/setupTests.ts

import '@testing-library/jest-dom';
--------------------------

Run:
    npx vitest
    -------
    Or in package.json
    ------
{
    "scripts": {
        "test": "vitest" (or) "vitest run" (Note: vitest run - runs and stops. Plain vitest runs and lizens)
    }
}
-------------------------------
Then:
    npm test

### I got an error on methods - Cannot find name 'it' - Cannot find name 'expect'
For this - in tsconfig.app.json types - I added "vitest/globals"
"types": ["vite/client", "vitest/globals"],

Convention
.test.tsx → "This is a test file"
.spec.tsx → "This file contains the specification/behavior"

Both run exactly the same.

Many Angular and enterprise projects prefer .spec.ts.

Why does it() exist?
It just makes test descriptions read like English.
Eg:
    It renders button.
    It calls onClick when clicked.
---------------------------------------------------------------------

Im using
Button.spec.tsx

describe('Button', () => {
  it('should render label', () => {});
});
